## 1. Multi-Factor Scoring Mathematical Model

Every candidate result generated by the multi-tier search engine is evaluated using a composite scoring function:

$$\text{FinalScore} = \left( S_{\text{match}} \times W_{\text{source}} \right) + B_{\text{window}} - P_{\text{active}} + B_{\text{recency}} + B_{\text{frequency}} + B_{\text{learned}} + B_{\text{context}}$$

Where:
- $S_{\text{match}} \in [0.0, 1.0]$: Base match quality from Tier 1–5 matching.
- $W_{\text{source}} \in [0.5, 1.5]$: Base weight assigned to resource source (Tab, Bookmark, History).
- $B_{\text{window}}$: Boost applied if the open tab resides in the current focused Chrome window.
- $P_{\text{active}}$: Penalty applied if the result is the current active tab.
- $B_{\text{recency}}$: Time-decayed recency boost.
- $B_{\text{frequency}}$: Historical visit frequency multiplier.
- $B_{\text{learned}}$: Query-specific local feedback boost.
- $B_{\text{context}}$: Co-occurrence boost based on currently active domain/project.

---

## 2. Source Weighting Hierarchy

By default, Chrome Navigator prioritizes resources that are actively in flight or deliberately saved:

| Source Type | Default Weight ($W_{\text{source}}$) | Configurable Range |
| :--- | :---: | :---: |
| **Pinned Item** | $1.40$ | $[1.0, 2.0]$ |
| **Open Tab** | $1.20$ | $[0.8, 1.6]$ |
| **Bookmark** | $1.00$ | $[0.6, 1.4]$ |
| **Browser History** | $0.70$ | $[0.3, 1.0]$ |

### 2.1 Soft Ordering Principle

Source weighting is **never a rigid boundary**. A history result with an exact title and URL match ($S_{\text{match}} = 1.0 \times 0.70 = 0.70$) will outrank an open tab that only matches via weak fuzzy alignment ($S_{\text{match}} = 0.35 \times 1.20 = 0.42$).

---

## 3. Window Locality & Contextual Boosts

### 3.1 Current Window Boost ($B_{\text{window}}$)

When two tabs have identical or similar match scores, the tab located in the **active Chrome window** receives a $+0.15$ boost over tabs in background windows. This minimizes disruptive cross-monitor window focus shifts.

### 3.2 Current Domain Boost ($B_{\text{context}}$)

If the user invokes Navigator on `github.com/company/repo`, other open tabs, bookmarks, or history entries sharing `github.com` or `company/repo` receive a contextual affinity boost of $+0.10$.

### 3.3 Current Project Context Heuristic

The engine analyzes URL subpaths (e.g. `/company/project-alpha/`). When multiple open tabs belong to the same project hierarchy, candidates within the same subpath are boosted.

---

## 4. Active Tab Suppression Policy ($P_{\text{active}}$)

Navigating to the tab in which Navigator was just summoned is almost always unintentional and redundant.

- **Default Behavior**: $P_{\text{active}} = 0.40$ (tab is demoted towards the bottom of the candidate list).
- **Hide Active Tab Setting**: When `settings.hideCurrentTab === true`, the active tab is completely excluded from search results.

---

## 5. Recency Boost & Exponential Decay Function

Recency boost $B_{\text{recency}}$ is computed using continuous exponential decay based on the time elapsed $\Delta t$ since the page was last visited:

$$B_{\text{recency}}(\Delta t) = M_{\text{recency}} \times e^{-\lambda \Delta t}$$

Where:
- $M_{\text{recency}} = 0.25$ (Maximum recency bonus).
- $\lambda = \frac{\ln(2)}{T_{\text{half}}}$ with half-life $T_{\text{half}} = 24\text{ hours}$.
- Items visited within the last hour receive near-maximum boost ($\approx +0.24$).
- Items visited 7 days ago decay to $\approx +0.002$.

## 6. Access Frequency Multiplier ($B_{\text{frequency}}$)

Frequency bonus uses a bounded logarithmic scaling function to prevent high-traffic sites (e.g. search engines) from permanently dominating the rankings:

$$B_{\text{frequency}}(V) = K_{\text{freq}} \times \ln(1 + V)$$

Where $V$ is the visit count recorded in Chrome history or Navigator logs, capped at $B_{\text{frequency}}^{\max} = 0.20$.

---

## 7. Local Frequency-Based Feedback (Query-Specific Learning)

Chrome Navigator features an **on-device, privacy-preserving learning feedback loop**. When a user types a specific query and selects a candidate item, the system records this association.

```typescript
export interface QuerySelectionRecord {
  query: string;               // Normalized query string (e.g. "prod")
  canonicalUrl: string;        // Destination canonical URL
  count: number;               // Number of times chosen
  lastSelectedAt: number;      // Epoch timestamp
}
```

### 7.1 Association Reinforcement

- If a user repeatedly types `prod` and selects `https://grafana.internal.net/dashboards`, the engine increases $B_{\text{learned}}$ for that specific URL when query matches `prod`.
- After 2–3 selections, this item automatically ranks #1 for `prod`.
- **Zero Cloud AI**: Completely deterministic, transparent, and executed locally in $< 1\text{ms}$.

### 7.2 Learning Privacy Controls

- **Clear Learned Data**: Instant one-click purge of all query-URL associations.
- **Toggle Learned Ranking**: Setting to disable learned associations entirely.
- **Private Search Sessions**: Temporary searches in private mode do not update learned weights.

---

## 8. Learned Weight Decay

Learned associations do not accumulate infinitely. If an association is not re-selected, its weight decays linearly every 30 days:
$$\text{Weight}_{t} = \text{Weight}_0 \times \max\left(0, 1 - \frac{\Delta t}{90\text{ days}}\right)$$

## 10. Result Layout Modes & Source Diversity Protection

### 10.1 Flat Ranking vs. Grouped View

Users can choose how results are rendered:
1. **Flat Ranking (Default)**: All results sorted purely by `FinalScore`. Provides the fastest single-key navigation experience.
2. **Grouped View**: Results categorized into visual sections (`OPEN TABS`, `BOOKMARKS`, `BROWSING HISTORY`).

### 10.2 Source Diversity & Quota Limits

To prevent browsing history from overwhelming open tabs or bookmarks (which are typically more actionable):
- **Per-Source Caps**: Max 5 tabs, 5 bookmarks, 10 history items.
- **Anti-Starvation Floor**: The top 2 most relevant open tabs are always reserved within the first 5 visible slots, provided their $S_{\text{match}} \ge 0.50$.
